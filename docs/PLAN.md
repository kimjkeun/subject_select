# 작업 계획

AI 과목 선택 도우미 웹앱을 위해 『2026학년도 2022 개정 교육과정 선택 과목 안내서』를
구조화 데이터로 변환하고, 그 위에 상담 웹앱을 올린다.

최종 수정: 2026-09-03

---

## 0. 원본 실측

| 항목 | 값 |
|---|---|
| 물리 페이지 | 182시트, A3 가로(1190×842pt) = **2쪽 펼침** |
| 실제 쪽 수 | **362낱쪽** (인쇄 쪽번호 최대 361) |
| 텍스트 레이어 | 있음 (스캔본 아님 → OCR 불필요) |
| 본문 분량 | 한글 24.3만 음절 / 공백제외 28.4만 자 ≈ **35~45만 토큰** |

전체를 컨텍스트에 넣을 수 없고, 넣을 필요도 없다. 이 문서는 긴 산문이 아니라
**과목·학과마다 동일한 스키마가 반복되는 카탈로그**이기 때문이다.

## 1. 방향 결정

### 채택: 구조화 추출 (Structured Extraction)

쪽 단위로 스키마를 뽑아 JSON DB를 만들고, 웹앱은 필요한 레코드만 컨텍스트에 주입한다.

### 기각: 벡터 RAG (청크 임베딩)

- 과목 한 건이 청크 경계에서 잘려 학점·평가정보가 누락된다.
- A3 2-up이라 텍스트 추출 시 좌우 다른 쪽이 한 줄에 섞인다. 청크 단위로는 이 오염을 못 잡는다.
- 과목이 100여 개뿐이라, LLM이 전체 색인을 직접 보고 고르는 편이 벡터 검색보다 정확하다.

### 기각: 파인튜닝

- 교육과정은 매년 개정되는데 재학습 비용이 든다.
- 학점·과목명 같은 사실 정보는 파인튜닝으로 안 박히고 오히려 환각이 는다.
- **출처(쪽수) 제시가 불가능해진다.** 학생·학부모 대상 서비스에서 근거를 못 대는 건 치명적이다.

## 3. 다음 작업 — 배치 추출 명세

낱쪽 259장을 각각 **이미지 1장 + 원시 텍스트**로 보내 스키마대로 JSON을 받는다.
259개 요청은 서로 의존성이 없어 전부 병렬 처리된다.

### 요청 1건의 구성 (subject 기준, 실측)

| 구성 | 토큰 |
|---|---:|
| system: 추출 프롬프트 (캐시) | 1,040 |
| 이미지: 150dpi PNG (1241×1754 → 1109×1568로 리사이즈) | 2,319 |
| 원시 텍스트 | ~1,685 |
| 출력 JSON | ~1,200 |

**이미지와 텍스트를 둘 다 넣는 것이 핵심.** 텍스트만으로는 표의 열이 뒤섞이고
(p.39 원시 텍스트는 `주요 학습 활동`이 `핵심 개념`보다 앞에 나온다),
이미지만으로는 긴 문장에서 오탈자가 난다. 프롬프트가 "이미지의 표 배치를 최종 근거로
삼는다"고 지시해 둘을 교차 검증시킨다.

### 배치 4개

| kind | 요청 | 입력 tok | 출력 tok | 업로드 |
|---|---:|---:|---:|---:|
| `subject` | 109 | 555k | 131k | 39.8MB |
| `major` | 120 | 576k | 144k | 39.5MB |
| `special` | 14 | 58k | 17k | 4.3MB |
| `appendix` | 16 | 65k | 19k | 3.7MB |
| **합계** | **259** | **1.25M** | **311k** | **87MB** |

### 비용·시간·한도

- **비용 약 $7** — Claude Opus 5 입력 $5/MTok, 출력 $25/MTok에 배치 50% 할인. 동기 호출 시 $14.
- **시간** — 대부분 1시간 이내, 최대 24시간. 결과는 29일 보관.
- **한도** — 배치당 요청 10만 건 / 256MB. 최대 배치가 39.8MB로 여유.
- 재실행 안전. 이미 JSON이 있는 쪽은 건너뛰므로 실패분만 다시 돌린다.

### 실행 순서

```bash
export ANTHROPIC_API_KEY=...
pip install anthropic
python pipeline/03_extract.py subject --sync -n 3    # 표본 3쪽으로 스키마 확정
python pipeline/03_extract.py subject                # 109건 배치 제출
python pipeline/03_extract.py subject --collect <batch_id>
python pipeline/05_verify.py
python pipeline/04_build.py
```

`subject` 자리에 `major`, `special`, `appendix` 를 넣어 반복.

### 미결정 — thinking 설정

`03_extract.py` 에 현재 thinking 설정이 없다. 뒤섞인 텍스트와 이미지를 대조해 표의
행·열을 맞추는 판단이 들어가므로 `thinking: {"type": "adaptive"}` 를 켜면 판독
정확도가 오를 것으로 보이나, 사고 토큰만큼 출력이 늘어 $7보다 비싸진다.

**결론 보류.** `--sync -n 3` 을 켠 것/끈 것 양쪽으로 돌려 표본 3쪽을 비교한 뒤 정한다.
비교 비용은 수십 센트.

### 비용 절감 관련 메모

프롬프트에 캐시를 걸어뒀으나 **절감액은 미미하다.** 공통 부분이 1,040토큰뿐이고
나머지 약 4,000토큰은 쪽마다 다르다 (Opus 5 최소 캐시 512토큰은 넘어 동작은 한다).
실제 비용을 좌우하는 건 이미지 토큰이라 아끼려면 dpi를 낮춰야 하는데,
**150dpi가 표 판독의 하한선에 가까우므로 낮추지 않는다.**

## 4. 웹앱 아키텍처 — 3계층

### 1계층. 항상 주입 (프롬프트 캐시)

`web/data/subject_index.json` — 전 과목 요약
(`과목명 + 교과군 + 유형 + 학점 + 한줄 + 키워드`). 과목당 약 184토큰,
109과목 기준 **약 20k 토큰**. 시스템 프롬프트에 올리고 캐싱하면 매 요청 실질 비용은
2k 토큰 수준. 이것만으로 AI가 전체 과목 지도를 항상 파악한다.

### 2계층. 필요 시 주입 (tool call)

`get_subject_detail(ids[])` 툴로 후보 과목의 전체 JSON만 꺼낸다.
과목 상세 1건 약 1,180토큰, 한 턴에 5~8건이면 충분 → 6~10k 토큰.

`major_subject_map.json` 이 학과↔과목 양방향 매핑을 제공하므로,
"○○학과 지망" 한마디로 후보를 좁힐 수 있다.

### 3계층. 규칙 검증은 코드로 (LLM 금지)

**졸업 학점, 교과별 최소 이수, 필수 이수 과목, 선이수 관계(대수→미적분Ⅰ),
2028 수능 반영 과목 — 전부 결정론적 validator가 판정한다.**

```
학생 선택 → [ validator (JS/TS) ] → 위반 목록 → AI는 "왜 문제인지 + 대안"만 설명
```

학생 인생이 걸린 숫자를 LLM이 환각하면 안 된다. AI는 설명과 상담만 담당한다.

## 5. 추출 원칙

1. **원문 그대로.** 요약·의역·문장 다듬기 금지. 없는 내용 생성 금지.
2. 모든 레코드에 `_source_page` 를 남겨 AI 답변이 안내서 쪽수를 근거로 댈 수 있게 한다.
3. 페이지에 없는 항목은 `null` 또는 빈 배열. 추측 금지.
4. 측면 색인 글자(Ⅰ Ⅱ Ⅲ)가 본문에 끼어드는 현상이 있어 프롬프트에서 명시적으로 제거시킨다.
5. `05_verify.py` 가 원문 대조로 환각·색인글자 잔존·빈 필드를 잡아 사람 검수 대상을 줄인다.

## 6. 알려진 이슈 / 주의

- **A3 2-up 스프레드.** 반드시 좌우로 나눈 뒤 처리해야 한다. 나누지 않으면 부록 등에서
  무관한 두 쪽이 한 줄에 섞인다.
- **인쇄 쪽번호 미인식 59쪽.** 간지·표지 등 푸터가 없는 쪽. `seq` 로 대체 추적.
- **학과의 관련 선택 과목 표기 불일치.** 안내서가 "제2외국어", "한문" 처럼 교과(군)
  이름으로 뭉뚱그린 경우가 있다. `04_build.py` 가 `unmatched_subject_names` 로 뽑아주므로
  별칭 사전을 만들어 해소한다.
- **`data/images/`(82MB), `data/pages/`(1.8MB)는 커밋하지 않는다.**
  `python pipeline/01_split.py 150` 으로 PDF에서 1분이면 재생성된다.
- **부록 반영과목 표는 열이 매우 많아 오독 위험이 가장 크다.** 프롬프트에서 판독이
  애매하면 `null` + `_uncertain: true` 로 남기게 했다. 사람 검수 우선순위 1순위.
